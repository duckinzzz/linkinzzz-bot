# Дизайн: кэш медиа по нормализованному URL поста

Дата: 2026-10-12
Ветка: `feat/media-cache`

## Цель

Не качать и не заливать в Telegram один и тот же пост дважды. Ценность — `file_id`
уже загруженного файла: переиспользование выкидывает из пути gallery-dl/yt-dlp,
ffmpeg, base64 и аплоад.

## Ключ: нормализуем ссылку сами

Ключ — не URL из сообщения как есть, а результат нашей нормализации. Резолв через
экстрактор не нужен: он давал канонический `post_url`, но требовал отдельного
дешёвого прогона метаданных **перед** проверкой кэша, то есть кэш всё равно
начинался с сабпроцесса. Нормализуя сами, получаем попадание вообще без прогонов.

Что делает нормализация:

- приводит к нижнему регистру хост, срезает `www.`, отбрасывает query и fragment,
  убирает завершающий слэш;
- для Instagram схлопывает формы пути одного и того же поста
  (`/p/<code>/`, `/reel/<code>/`, `/reels/<code>/`, `/tv/<code>/` → `instagram.com/<code>`);
- для YouTube достаёт id оттуда, где он лежит: `watch?v=<id>` → `youtube.com/<id>`,
  `youtu.be/<id>` и `/shorts/<id>` — туда же;
- для TikTok — `/video/<id>` → `tiktok.com/<id>`;
- остальное — `host + path` без query.

Проверенное основание (прогон 2026-10-12): один и тот же IG-пост открывается как
`/reel/DeToSP9AwFv/?rpxt=...`, `/p/DeToSP9AwFv/` и `/reels/DeToSP9AwFv/` — три
разных строки, один контент. Shortcode уникален, поэтому схлопывание до кода
безопасно.

**Режим отказа — промах, а не подмена.** Если ссылка структурно отличается от
того, что умеет нормализация, будет промах и повторная выкачка. Отдать чужой
файл нормализация не может: у Instagram/YouTube/TikTok id уникален, а в общем
случае ключ — конкретный host+path. Устаревание контента по одному и тому же
пути ограничено TTL.

## Схема БД

`sqlite3` из стандартной библиотеки, файл на volume, путь из env `CACHE_DB_PATH`
(по умолчанию `/app/data/cache.db`). Отдельная таблица под медиа не нужна:
ключи медиа не участвуют в поиске.

```sql
CREATE TABLE IF NOT EXISTS posts (
    key        TEXT PRIMARY KEY,   -- нормализованный URL
    caption    TEXT,
    media      TEXT NOT NULL,      -- JSON: [{file_id, kind, width, height}, ...] в порядке поста
    updated_at REAL NOT NULL
);
```

## Поток

1. `key = normalize_url(text)`.
2. `SELECT` из `posts`.
3. Попадание → собрать `InputMediaPhoto/Video(media=file_id, ...)` в том же
   порядке и отправить тем же кодом, что и обычная отправка.
4. Промах → скачивание как сейчас (`download_post_json`) → `_send_payload`.
5. `_send_payload` сейчас выбрасывает возвращённые `Message` — начинаем их
   собирать: у одиночной отправки это `Message`, у `answer_media_group` —
   `list[Message]` в том же порядке, что и медиа. Из каждого берём
   `photo[-1].file_id` либо `video.file_id` плюс `width`/`height` и пишем в кэш.

Порядок сообщений совпадает с порядком медиа: `answer_media_group` сохраняет
порядок, чанки по 10 идут последовательно.

## Ошибки и инвалидация

- `file_id` может протухнуть. При `TelegramBadRequest` на кэш-ветке — удалить
  запись и пройти обычный путь скачивания.
- Ошибки (`NoMedia`, `UnsupportedSite`, `TooLarge`, `InappropriateContent`)
  не кэшируются: контент может появиться позже.
- TTL: чистка записей старше `CACHE_TTL_DAYS` (по умолчанию 30) на старте.
- Гонка: два одновременных запроса одной ссылки. `asyncio.Lock` на ключ, чтобы
  второй ждал первый и попал в кэш, а не качал параллельно.

## Затрагиваемые файлы

- `utils/cache.py` — новый: нормализация, схема, get/set/delete, TTL.
- `handlers/text.py` — проверка кэша, сбор `file_id` из ответов, кэш-ветка отправки.
- `core/config.py` — `CACHE_DB_PATH`, `CACHE_TTL_DAYS`.
- `docker-compose.yml`, `docker-compose.DEV.yml` — volume под `/app/data`.
- `.dockerignore` — чтобы БД не попала в контекст сборки.

## Тестирование

Тестов в проекте нет вообще. Нормализация — чистая функция, проверяется
таблицей входов/выходов; кэш — round-trip по sqlite. `pytest` отдельной
dev-группой **не добавляю** — в фичу молча не тяну, скажешь отдельно.

Проверка на деве: два запроса одной ссылки подряд, в логах `cache MISS` затем
`cache HIT`, второй без скачивания; вариант с `?igsh=...` и формой `/p/` вместо
`/reel/` должен попадать в тот же ключ.

## Вне объёма

- Резолв канонического URL через экстрактор.
- Частичные попадания по карусели: набор хранится целиком, при неполном —
  перекачиваем пост.
- Общий ключ между gallery-dl и yt-dlp.
